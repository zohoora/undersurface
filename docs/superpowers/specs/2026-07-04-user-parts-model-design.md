# User Parts Model (+ Lexicon Rider) — Design

**Date:** 2026-07-04
**Status:** Approved (ontology, order, birth model, consent flow, and role-tagging chosen by Arash via brainstorming Q&A; design sections approved with "Implement autonomously")
**Program context:** Sub-project 1 of the Unique Companion program (companion-parts ontology decided: the 7 seeded parts are the COMPANION's parts; the user's parts are a new model, mapped from the user's material and named in the user's own words).

## Decisions (locked)

| Question | Decision |
|---|---|
| Ontology | Seeded 7 = companion's parts. User parts = new model from session material |
| Build order | SP1 user parts (+lexicon) → SP2 companion interiority → SP3 interaction → SP4 place |
| Part birth | **Proposed by companion, confirmed by user** — named in the user's own words; rename/retire anytime |
| Consent flow | In-reply offer + **inline confirm card** (deterministic UI event; never inferred from prose) |
| Role tagging | Soft internal `stance` descriptor, regenerated over time, **never shown to the user** |

## Data model

`userParts` collection (registered in db proxy, `src/types/index.ts`, dataExport, functions `USER_SUBCOLLECTIONS`):

```ts
export interface UserPart {
  id: string
  name: string          // user's words (tentative until confirmed); editable
  description: string   // one sentence; editable
  stance: string        // internal soft descriptor; never surfaced; regenerated by reflection
  status: 'candidate' | 'active' | 'retired'
  evidence: { sessionId: string; quote: string; observedAt: number }[]  // cap 8, quotes ≤ 15 words
  sessionsSeen: number  // distinct sessions with evidence; proposal threshold = 2
  dismissedCount: number // 1 → cooling-off; 2 → retired permanently
  proposedAt?: number   // set only when the finalized message actually contained the marker
  confirmedAt?: number
  retiredAt?: number
  lastActiveAt: number
  createdAt: number
  updatedAt: number
}
```

Caps: 9 active, 5 candidates (new candidates dropped when full — precision over coverage). `PersonalFacts` gains `lexicon?: string[]` (cap 12).

## Detection — reflection-pass extension

`buildSessionReflectionPrompt` gains a `userParts` option (existing candidates + active parts: id/name/description/stance) and two new output fields:

```
"partObservations": [
  { "partId": "existing-id-if-this-matches-a-listed-part", "quote": "exact phrase (max 15 words)", "stance": "updated soft descriptor" },
  { "tentativeName": "the part that braces", "description": "...", "stance": "...", "quote": "..." }
],
"coinedPhrases": ["phrases the WRITER coined this session (max 3)"]
```

Rules mirror the personalFacts precision rails: literal recurring patterns only, never metaphor ("I told my anxiety to be quiet" is not a sighting), never distress content, bias to omit, at most 2 observations per session. The LLM does existing-part matching by id (it sees the list) — no client fuzzy-matching.

`userPartTracker.ts` (pure functions) merges observations into the collection: append evidence (cap 8), bump `sessionsSeen` once per session per part, update `stance` and `lastActiveAt` on matches, create candidates (respecting caps), never resurrect `retired`. Malformed observations dropped silently.

## Proposal + consent

- **Arming:** `loadTherapistContext` (flag-gated) loads userParts; returns `activeUserParts` and at most one `partProposalCandidate` (status candidate, `sessionsSeen >= 2`, `dismissedCount === 0` or one dismissal older than 5 sessions — tracked via `proposedAt`/`dismissedCount`; simplest v1 rule: eligible iff `dismissedCount === 0` and (`proposedAt` unset or > 7 days old)).
- **Prompt:** `partProposal` block — offer ONE noticing, tentatively, in the flow of a normal reply, wrapping the offer phrase in the marker `[<phrase>](#propose-part:<id>)`. Never on the opener, never during grounding, never in the same build as `pivotDirective` or `softenStance` (one intervention at a time; enforced at the wiring layer, grounding also enforced at the prompt layer).
- **Marker handling:** parsed client-side (same family as recommendation segments). The marker phrase renders as normal text; a `PartProposalCard` renders beneath the message: editable name field (pre-filled with the tentative name), Confirm / "Not quite".
  - Confirm → `status: 'active'`, `confirmedAt`, name from the field.
  - Dismiss → `dismissedCount + 1`; second dismissal → `status: 'retired'`.
- **Consume-once:** after the therapist message finalizes, IF the text contains the marker, stamp `proposedAt` (fire-and-forget). If the model ignored the instruction, nothing is stamped and the candidate re-arms next session. One proposal inclusion per session (wiring ref).

## Prompt integration

- **Active-parts block** ("Parts of the writer you both know"): name + description per active part; stance shapes tone via a general instruction, never quoted. Hard rules in-block: refer to parts only by the writer's names, never coin part names in conversation (proposals are the only birth channel), no parts language during grounding. Names/descriptions wrapped as untrusted content.
- **Lexicon block** ("Shared language"): the capped list, "their words, their sense — use naturally and sparingly, never explain them back."
- Voice sessions receive the active-parts + lexicon blocks (read-only); proposals are text-surface-only in v1.

## Management UI (minimal)

"Parts of you" section in the existing Settings surface, visible when the flag is on and any non-retired part exists: list of active parts (name, description, inline rename, Retire). Candidates are not shown (they don't exist to the user until offered). Full constellation view is SP4.

## Flag, safety, i18n

- Experimental flag `userParts` (default OFF) gating detection, proposals, prompt blocks, and the Settings section. Lexicon rides the same flag.
- All blocks suppressed under grounding. Evidence quotes ≤ 15 words. Export includes `userParts`; deletion registry covers it automatically.
- New user-facing strings (card + settings section) added to all 17 locales.

## Testing

- `userPartTracker.test.ts` — merge, per-session dedup of `sessionsSeen`, caps, retired-never-resurrected, malformed dropped.
- `sessionReflectionEngine.test.ts` — partObservations parsed + tracker invoked, lexicon merged with cap, flag gating, malformed tolerated.
- `therapistPrompts.test.ts` — active-parts block (present/absent/grounding/untrusted wrap), proposal block rules (never opener/grounding), lexicon block.
- `partProposalParser.test.ts` — marker extraction, clean text, malformed markers ignored.
- `PartProposalCard.test.tsx` — confirm writes active+name, dismiss increments, second dismissal retires.
- `useSessionStream.test.ts` — proposal armed once per session, exclusivity vs pivot/soften, `proposedAt` stamped only when marker present in finalized text.
- Live eval (`npm run test:parts`, env-gated `RUN_PARTS_EVAL=1`) — precision confusables: metaphor, one-off event, distress content (must yield no observations), genuine recurring pattern (must be observed), existing-part matching (must match by id, not duplicate).

## Non-goals (v1)

- No constellation/visual map (SP4). No companion-part↔user-part relationship records (SP3). No proposal cards in voice. No user-authored part creation UI (the confirm card's editable name is the only authoring surface).
